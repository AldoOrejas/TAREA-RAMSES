Illustration of a GitHub Repository Model

Git & GitHub Practice — Repositories, Branches, Commits and Workflows

Command & Action Legend

  • 1 git clone <url> (Copy repo to local)
  • 2 git switch -c develop (Create develop)
  • 3 git switch -c feature/* (Create feature)
  • 4 git add . & git commit -m
  • 5 git push -u origin <branch>
  • 6 GitHub PR: Create base ← compare
  • 7 git merge --no-ff (Merge commit)
  • 8 git tag -a v1.0.0 -m "Release"

Branch Functions & Flow

  • main: Production code. Starts at init commit. Receives releases & hotfixes.
  • develop: Pre-production integration. Starts from main. Receives features & hotfixes.
  • feature/*: Specific feature work. Starts from develop. Merges back to develop.
  • hotfix/*: Urgent bug fixes. Starts from main. Merges to BOTH main & develop.

Shapes & Symbols

  • ⚪ Circle Nodes: Ordinary Commits (feat:, fix:, style:, docs:)
  • 🔲 Square Nodes: Explicit Merge Commits
  • ➡️ Solid Arrows: Direct Branch / Integration Flow
  • ⬇️ Dashed Arrows: Push to Remote (origin)
